# 控件如何上屏

> 这篇补一个从第一篇就欠着的问题。它是读者翻开 M1 代码时的第一反应，也是 M1 里唯一没有正面回答过的事：
>
> **我一行绘制代码都没写，按钮怎么出现的？**

界面上的输入框、按钮、标签都摆在我的客户区里，那行字也是我写的。我翻遍自己的源文件，动手画东西的地方只有一处。`WM_PAINT` 里那行 `DrawTextW` 是我写的，别处我一句都没写。

`DrawTextW` 只画了我那行字。其余的控件我一行代码都没写，它们的样子却一点没变，鼠标移过去的时候还会变色，按下去的时候还会陷进去。

## 按钮自己就是一个窗口

控件不是一张贴上去的图片。它跟主窗口的来路一样，都是系统创建出来的窗口。我能管的只有父窗口和一块矩形，父窗口挪了，它的位置也跟着变。

创建控件的那一行是我写的，字符串参数报的只是类名，剩下的活全落到 `CreateWindowExW` 里。

```cpp
hint_ = &add_native(0, L"STATIC", L"（……）", WS_CHILD | WS_VISIBLE);
```

`L"STATIC"` 不是我注册的窗口类，系统早就把它连同配套的窗口过程一起备好了。名字我写错了一位，`CreateWindowExW` 交回来的就是 `NULL`，`GetLastError()` 给出的值是 1407，意思是系统里压根没有叫这个名字的窗口类。我第一次手敲的时候把 `STATIC` 记成了 `STATIK`，界面上少了那行灰字，日志里多了个 1407。

类名我报对了以后，重画的事就交给系统了。控件要刷新的时候，收到 `WM_PAINT` 的是系统的窗口过程，字体和边框都是它画的，我只在旁边看。

代价是我对这些像素没有控制权。换来的东西平时看不见，缺了才知道难受。

我把系统切到高对比度模式，我的 `DrawTextW` 那行字还是白底黑字，旁边的按钮已经把边框换成了亮黄色，宽度还粗了一圈。

`EDIT` 的中文输入法早就接好了，候选框自己就贴到光标底下了，这些代码我一行都没写。真到自己画输入框的时候，那串 `WM_IME_*` 消息就得由我自己接。

讲述人读到按钮的时候，报出的名字和角色都是控件自带的，不用我写一行。

M2 第 3、5 档要补的正是输入法和无障碍。等我改成自绘，这两样得由我从头接起来。

## 同一个按钮，两个年代的长相

我看到系统从来没把按钮画成固定的模样，每画一次都要去问一遍当前的主题。常态、悬停、按下、禁用问的都是同一份主题数据。

这些调用住在我链接的 `UxTheme` 里。主题那侧提供的 `OpenThemeData` 和 `DrawThemeBackground` 大致是一对，控件报的是自己现在处在哪个状态，外貌的决定权在主题手上。

第一篇里我见过一次怪现象，到这里就说得通了。不挂 manifest 的时候，按钮的样子跟 Windows 95 一样。边框是两道灰白的高光线，按下去的时候整块往右下挪一个像素，同一种灰的底色从来不动。

我把这段声明补进 manifest，同一个按钮立刻换成圆角的样子，按下时是深一号的蓝，挪动的位移也没有了。

```xml
<assemblyIdentity type="win32" name="Microsoft.Windows.Common-Controls"
                  version="6.0.0.0" processorArchitecture="*"
                  publicKeyToken="6595b64144ccf1df" language="*"/>
```

它声明的是依赖 Common Controls 第六版。少了这一句，我拿到的就是第 5 版那套画法，也就是 XP 之前的观感，按钮也就成了扁平的灰块。代码我一行没改，外观就换了一副。决定咱们看到的按钮长相的，就是 manifest 里的那句声明。

## DC 那头不是屏幕

`WM_PAINT` 里我拿到的那块 DC，落笔的地方不是屏幕。它背后是一块由系统维护的位图。**重定向表面**是系统给这块位图起的名字，英文里的写法是 redirection surface。

从 Vista 起每个顶层窗口都有自己的重定向表面。我在上面画的每一笔都落在那块位图里，屏幕上的像素一个也没动。

真正把画面送出去的是 DWM。它的全名是桌面窗口管理器，干的活就是把各个窗口的表面合成成一张图，我改不到中间任何一步。

窗口挪动或者被别的窗口盖住，我都不需要重画。系统手上留着的是那块表面，露出来的时候照着贴回去就行。

我没画到的区域也不会变成黑块，这一层底下有系统替我兜着。

窗口外面的那圈圆角和阴影，我一行代码都没碰，它们全落到了这一层。

```
你改了某个值
   ↓  （原生控件：系统替你调；自绘：得你自己调）
InvalidateRect(hwnd, 某块矩形, TRUE)      把一块矩形标脏
   ↓
消息队列空闲时，系统合成一条 WM_PAINT
   ↓
BeginPaint  校验脏区、还给你一个 DC
   ↓
DC 对应的是【重定向表面】，不是屏幕
   ↓
EndPaint
   ↓
DWM 把表面合成上屏
```

整条链上我自己能伸手的地方只有 `InvalidateRect` 那一行。值改完了不标脏，后面的一长串都不会启动。

## 那行字为什么一直不动

我留在第一篇里的痛点 5，放到整条链上看就很直白了。

```cpp
SetWindowTextW(label_, kText);   // 系统那侧会自己调 InvalidateRect
drawn_->text.set(kText);         // 只是改了内存里的一个值
```

系统在窗口过程里替第一行调了一次标脏，所以它立刻就更新了。第二行只改掉了内存里的一个值，其实没人替它标脏。重定向表面还是旧的，我看到的自然也是旧画面。

屏幕上的样子我记得很清楚：输入框里的新文字已经显示出来，右边那行字的内容还是旧的。我把窗口拖出屏幕边缘再拖回来，系统的重绘也帮不上忙。

第五层把标脏挪进了写入点，改值的时候顺手就标了，我在外面不用补任何一句。

**我一开始问的那句，Win32 给的答案是：系统画、系统合成、您只负责说这块脏了**。

## M2 第 2 档把它整条换掉

M2 第 2 档换掉的是整条链。那一档我得把上屏从 GDI 换成 Direct2D 加 DirectComposition，窗口样式里还多了一条硬要求。

```cpp
WS_EX_NOREDIRECTIONBITMAP
```

它做的事就是把重定向表面拿掉。表面没了以后，`BeginPaint` 交回的 DC 是个空壳，我往上画的每一笔都到不了屏幕。

视觉样式那一层也归我自己模仿，按钮的四种状态、圆角半径、深浅两套配色，都由我一个个补。

合成也不归系统兜了，我得自己维护一棵视觉树，谁盖在谁上面由我排。

我拿到的是逐像素 alpha、零闪烁，还有现代 Windows 上的通透质感。

刚才系统替我借来的几样东西，到了那一档全得自己补。这就是 M2 第 2 档要付的代价。

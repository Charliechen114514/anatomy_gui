# 控件如何上屏

> 这篇补一个从第一篇就欠着的问题。它是读者的第一反应，也是 M1 唯一没正面回答的事：
>
> **我一行绘制代码都没写，按钮怎么出现的？**

把整个 M1 的代码翻一遍，你会发现自己写的"画东西"只有一处 —— `WM_PAINT` 里那行 `DrawTextW`。而界面上有输入框、按钮、标签、还有那行字。前三个是谁画的？

答案不在你的代码里。它在三件事上。

## 一、控件是窗口，所以它的绘制归系统

回去看创建控件那一行：

```cpp
hint_ = &add_native(0, L"STATIC", L"（……）", WS_CHILD | WS_VISIBLE);
```

它最后落到 `CreateWindowExW`，用的是 `L"STATIC"` 这个**类名**。这个类不是你注册的 —— 是系统预先注册好的。系统为它准备了完整的窗口过程。

于是当控件需要重画时，收到 `WM_PAINT` 的是**系统的窗口过程**，不是你的。`BeginPaint`、挑字体、画边框、画文字，全在那一侧完成。

**代价是这些像素你没有控制权**；好处是它免费带上了三件你自己做要花很久的事：

- **主题**：深浅色切换、高对比度模式下自动换配色
- **输入法**：`EDIT` 天然接了 IME，中文输入能打进去
- **无障碍**：它自带"我是编辑框、我的值是什么"，讲述人能读

（第二、三件正是 M2 第 3、5 档要"还债"的地方 —— 一旦自己画，这三样都得自己补。）

## 二、它的样子来自"视觉样式"，不是一个画法

系统控件并不是把按钮画成固定模样。它会去问一个叫**视觉样式**的东西：当前主题下，按钮的四种状态（常态、悬停、按下、禁用）各长什么样？

这类调用住在 `UxTheme` 里，大致是 `OpenThemeData` / `DrawThemeBackground` 这一套。**控件只负责说"我现在是按下状态"，长什么样由主题决定。**

这就解释了第一篇里那个现象：**不挂 manifest 时按钮长得像 Windows 95。**

manifest 里这段是解药：

```xml
<assemblyIdentity type="win32" name="Microsoft.Windows.Common-Controls"
                  version="6.0.0.0" processorArchitecture="*"
                  publicKeyToken="6595b64144ccf1df" language="*"/>
```

它声明"我依赖 Common Controls 第六版"。没有这个声明，系统按第 5 版（XP 之前）那套画法走 —— 于是你就看到了那个扁平古董样子。**同一行代码，两种外观，差别只在有没有这句声明。**

## 三、像素最后不是直接去屏幕的

这是最容易被忽略、也最重要的一环。

你在 `WM_PAINT` 里拿到的那块 DC，**不是屏幕**。自 Vista 起，每个顶层窗口都有一块自己的**重定向表面**（redirection surface）—— 一块系统替你维护的位图。你画的是它。

然后 DWM（桌面窗口管理器）把各个窗口的表面**合成**成最终的画面。所以：

- 你的窗口"没画到"的区域不会变成黑块 —— 有另一层兜着
- 窗口移动、被遮挡、被拖动时，你不需要重画一遍 —— 系统手上有那块表面
- 圆角、阴影、动画这些窗口级效果，都在这一层

完整的时间线是这样：

```
你改了某个值
   ↓  （原生控件：系统替你调；自绘：得你自己调）
InvalidateRect(hwnd, 某块矩形, TRUE)      把一块矩形标脏
   ↓
消息队列空闲时，系统合成一条 WM_PAINT
   ↓
BeginPaint  校验脏区、还给你一个 DC
   ↓
DC 对应的是【重定向表面】，不是屏幕
   ↓
EndPaint
   ↓
DWM 把表面合成上屏
```

## 回到痛点 5：那行字为什么不动

现在再看第一篇里那个故意的 bug，原因就很物理了：

```cpp
SetWindowTextW(label_, kText);   // 系统那侧会自己调 InvalidateRect
drawn_->text.set(kText);         // 只是改了内存里的一个值
```

第一行能更新，是因为"标脏"这件事发生在系统的窗口过程里。第二行在那个版本里**没有任何人标脏** —— 于是重定向表面没变，DWM 合成的自然还是旧画面。

所以痛点 5 的修法不是"记得补一句 `InvalidateRect`"，而是**让写入点本身就是标脏的唯一出口**。这就是第五层做的事。

**"控件如何上屏"这个问题，在 Win32 里有三个答案：系统画、系统合成、你只负责说"这块脏了"。**

## 这一课通向哪里

记住这条链，因为 **M2 的第 2 档会把它整条换掉**。

那一档要把上屏从 GDI 换成 Direct2D + DirectComposition，而 DComp 路线的门是一句窗口样式：

```cpp
WS_EX_NOREDIRECTIONBITMAP
```

它做的事情就是**把重定向表面拿掉**。拿掉之后：

- GDI 彻底画不出东西（`BeginPaint` 给你的是个空壳）
- 上面第二条（视觉样式）得自己模仿
- 第三条（合成）从"系统兜着"变成"你自己维护一棵视觉树"
- 换来的是逐像素 alpha、零闪烁、以及现代 Windows 那种质感

**这三条正是 M2 第 2 档要付的账。** 现在你已经知道那笔账是怎么算出来的了。

# 落回具象 · 同一件事，两种写法

> 第 3 步。这一步原本叫做"用框架把同一个 demo 重写一遍" —— 但**它已经被前面五层做掉了**：每一层都顺手把 demo 迁了过去（不迁就没法验证"那处别扭消失了"）。
>
> 所以这一步做的不是重写，是**算总账**。

## 五条痛点，五种解法

| # | 裸版的样子 | 框架版的构造 | 解决它的那一层 |
|:--:|:---|:---|:---|
| 1 | 五个文件作用域的全局变量 | `Window` 持有 `hwnd_`；demo 是它的子类，控件是成员 | 窗口对象 |
| 2 | ID 常量 + `CreateWindowExW` + `switch` 分支，三处 | 一个节点：`add_native(...)` 一行 | 控件树 |
| 3 | 窗口过程里判断"哪个是按钮、点了干什么" | 控件只表态**收不收 / 处理了没有**，路由归 `EventRouter` | 事件路由 |
| 4 | 七个常量 + 五行算术 + 四次 `set_bounds` | 每个节点声明 `preferred_size`，`StackLayout` 算位置 | 布局 |
| 5 | 改了字符串，却没人失效那块矩形 | `Property<T>` 变化 → `invalidate()` 冒泡到根 → `InvalidateRect` | 属性与重画 |

## 逐条对照

**状态放哪。**

```cpp
// 裸版
static HWND g_edit_hwnd   = nullptr;
static wchar_t g_drawn_text[256] = L"（……）";
```
```cpp
// 框架版
class DemoWindow : public Window {
    NativeWidget* edit_   = nullptr;
    DrawnLine*    drawn_  = nullptr;
};
```

**加一个控件。**

```cpp
// 裸版：ID 常量在文件开头，创建在中段，响应分支在另一个 switch 里
constexpr int kIdLabel = 1003;
...
g_label_hwnd = CreateWindowExW(..., reinterpret_cast<HMENU>(static_cast<INT_PTR>(kIdLabel)), ...);
...
if (LOWORD(wParam) == kIdLabel && ...) { ... }
```
```cpp
// 框架版：一行创建，响应下一行就装上
label_ = &add_native(0, L"STATIC", L"…", WS_CHILD | WS_VISIBLE);
label_->set_handler([this](Event& e) { /* 就在这儿 */ });
```

**谁决定重画。**

```cpp
// 裸版：靠人记得
lstrcpynW(g_drawn_text, text, 256);
// 然后……忘了 InvalidateRect，界面就停在旧状态
```
```cpp
// 框架版：写入点就是排重画的唯一出口
DrawnLine() { text.on_changed([this] { invalidate(); }); }
...
drawn_->text.set(kText);
```

## 那条作业：加第四个控件，到底改几行

第 1 篇留的作业是"数数你改了几处"。现在有真实数字了。

我在框架版**真加了一个提示用的 `STATIC`**，改动是：

```cpp
NativeWidget* hint_ = nullptr;                                              // ① 成员
hint_ = &add_native(0, L"STATIC", L"（我是第四个控件……）", WS_CHILD | WS_VISIBLE);  // ② 创建
hint_->set_preferred_size(Size{.width = 0, .height = 24});                   // ③ 尺寸
```

| | 数字 |
|:---|:---|
| 逻辑改动 | **3 行** |
| 物理行净增 | **4 行**（254 → 258，clang-format 折了一行） |
| 落在几处 | **1 处** —— 全在 `create_controls` 里 |
| 要不要碰事件路由 | 不用（这个控件不需要响应） |
| 要不要重算坐标 | 不用 |

编译通过，控件数变成 4，点击链路照常。

> **所以第 1 篇那句"只改一行"是错的 —— 真实是 3 行。** 那句是我当时顺手写下的口号，这里更正。
>
> 但真正的变化不在行数上。按裸版的写法，同等改动要落在**五个地方**：ID 常量、全局 HWND、`CreateWindowExW`、`WM_SETFONT`、以及**布局算术**（其中"插在中间"还要把下面每一项的 `Top` 重算一遍）—— 大约十一行。而且三处之间没有任何编译期联系，漏一处只会得到一个"点了没反应"或"位置怪怪"的界面。
>
> 框架版这 3 行是**集中**的。行数少了不多，但"该改的地方只有一个"这件事，才是这一整套抽象买到的东西。

## 总账

| | 总行 | 纯代码 |
|:---|--:|--:|
| 裸版（`app/m1a_naked.cpp`，冻结保留） | 277 | 140 |
| 框架版 demo（`app/demo.cpp`） | 254 | — |
| 框架层（`framework/` + `platform/`） | — | — |
| **全部（含裸版与 manifest）** | **1439** | **662** |

骨架从 277 行长到 1439 行 —— 但其中 **777 行是注释**，而注释里很大一部分是本仓库对头文件强制的 doxygen。

**抽象不压缩代码。** 它做的事情是：让每一件事有唯一该在的地方。

- 窗口的生命周期 → `Window`
- 控件的身份与树 → `Widget`
- 事件该给谁 → `EventRouter`
- 位置 → `Layout`
- 状态变化之后谁负责刷新 → `Property` + `invalidate`

五层之前，这些东西分别散在全局变量、`CreateWindowExW` 的实参、一个越来越长的 `switch`、一段手算算术、以及**一个必须被人记住的 `InvalidateRect`** 里。

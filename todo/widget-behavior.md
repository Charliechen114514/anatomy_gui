# 抽象的控件需要哪些行为（控件行为清单）

> **一份文档，三种用法**：
> 1. **抽象阶段的产出物** —— M1b 里读者自己回答这些问题；回答完，接口就长出来了

## 二、清单

### A · 身份与树

| # | 控件必须回答的问题 | M1 谁做 | M2 谁做 | 怎么算做到了 |
|:--:|:---|:---|:---|:---|
| A1 | 我是谁（稳定的 id，用来查表和映射事件）？ | 框架分配 | 同 | 按 id 能找回控件 |
| A2 | 我的父、子、兄弟是谁？顺序如何（顺序就是 z-order）？ | 框架 | 同 | 插入顺序决定叠放顺序 |
| A3 | 谁拥有我、我什么时候死？ | 框架（`unique_ptr` + 析构自动解绑） | 同 | 删掉控件后，订阅它的回调不再触发 |
| A4 | 从任意节点怎么遍历整棵树？ | 框架（深度优先，布局/绘制/命中共用同一次遍历） | 同 | 一次遍历覆盖全部节点 |

### B · 几何

| # | 控件必须回答的问题 | M1 谁做 | M2 谁做 | 怎么算做到了 |
|:--:|:---|:---|:---|:---|
| B1 | 我的固有尺寸是多少（由内容决定）？ | 框架（原生控件向系统要） | 同 | 文本变长，控件变宽 |
| B2 | 我能被压到多小、拉到多大？ | 框架（min/max 约束） | 同 | 窗口缩到很小，布局不崩 |
| B3 | 我最终的矩形由谁定？ | **布局**（控件无权决定） | 同 | 控件代码里没有 `SetWindowPos` |
| B4 | 内边距 / 外边距算谁的？ | 控件的属性，**布局消费**（CSS box model） | 同 | 改 padding，布局立刻重排 |
| B5 | 一个点在我的坐标系里是哪儿？ | 框架（本地 ↔ 父 ↔ 屏幕） | 同 | 命中测试落在正确的坐标系里 |
| B6 | 我不可见时还占位置吗？ | 框架（**两个开关分开**：画不画 / 参不参与布局） | 同 | 隐藏的控件不画，但仍占位 |

### C · 绘制

| # | 控件必须回答的问题 | M1 谁做 | M2 谁做 | 怎么算做到了 |
|:--:|:---|:---|:---|:---|
| C1 | 我怎么出现在屏幕上？ | 系统（原生节点）/ 框架（自绘节点） | 框架 | 自绘节点由 `Painter` 画，原生节点 `onPaint` 为空 |
| C2 | 我什么时候要重画？ | 框架（`invalidate`，局部 / 整体） | 同 | 属性变了自动重画，不用手写 `InvalidateRect` |
| C3 | 我的绘制会被谁裁掉？ | **不归控件**：Window 统一裁剪 + 平台的 `WS_CLIPCHILDREN` | 框架 | 重叠控件不会互相擦花 |
| C4 | 尺寸变了要不要重画？ | 框架（布局完成后自动失效） | 同 | 缩放窗口，内容重排且不闪 |
| C5 | 我的外观随状态变吗（hover / pressed / disabled / focused）？ | 系统（原生控件自带） | 框架 | 自绘按钮三态外观不同 |

### D · 输入与事件

> **这一段是本次拍板最重的地方**：事件路由由**专门的组件**（`EventRouter`）负责，**控件不碰路由**。控件只表两个态：**我收不收**、**我处理了没有**。

| # | 控件必须回答的问题 | M1 谁做 | M2 谁做 | 怎么算做到了 |
|:--:|:---|:---|:---|:---|
| D1 | 这个点是不是落在我身上？ | 系统（子 HWND）/ 框架（自绘节点，**M1 就立 `hitTest` 接口**） | 框架（全部自己算） | 点在控件上，事件才到它 |
| D2 | **我收不收**这个事件？ | 控件表态 | 控件表态 | 不感兴趣的控件收不到 |
| D3 | **我处理了没有**？ | 控件表态（`onEvent` 返回值） | 同 | 返回"未处理"的事件继续往上冒泡 |
| D4 | 事件怎么走到我这儿？ | **不归控件** —— `EventRouter`：命中 → 捕获 → 目标 → 冒泡 | 同 | 嵌套控件里点最里层的那个 |
| D5 | 鼠标进出 / 按下 / 移动 / 抬起 / 双击 / 滚轮怎么收？ | 系统投递 + 框架翻译成类型化事件 | 框架 | 自绘控件也能收到 hover |
| D6 | 拖动时鼠标出了我的范围，我还收得到吗？ | 系统（捕获） | 框架（捕获） | 拖动中移出控件，仍收到移动事件 |
| D7 | 我能拿键盘焦点吗？拿到 / 失去时做什么？ | 系统 | 框架 | Tab 能在控件间移动焦点 |
| D8 | 文本输入接不接输入法？ | 系统白得（原生 `EDIT`） | 框架（TSF） | 中文输入法能打进去 |

### E · 状态

| # | 控件必须回答的问题 | M1 谁做 | M2 谁做 | 怎么算做到了 |
|:--:|:---|:---|:---|:---|
| E1 | 我的状态存在哪、谁在听？ | 框架（`Property<T>` + `changed`） | 框架（升级为依赖感知内核） | 改属性有通知 |
| E2 | 状态变了，谁需要知道？ | 框架（布局重排 / 渲染重画 / 绑定同步，各取所需） | 同 | 改 `text`，自动重排 + 重画 |
| E3 | enabled / visible / focus 会级联到子树吗？ | 框架（enabled、visible 级联；focus 不级联） | 同 | 禁用父控件，子控件也点不动 |

### F · 无障碍（M2 做，但清单现在就要列）

| # | 控件必须回答的问题 | M1 谁做 | M2 谁做 | 怎么算做到了 |
|:--:|:---|:---|:---|:---|
| F1 | 我叫什么、什么角色、值多少？ | 系统白得 | 框架（UIA provider） | 讲述人能读出按钮的名字 |
| F2 | 我现在什么状态？ | 系统 | 框架 | 讲述人能读出"已按下" |

### G · 与平台的关系

> 这一组决定前面六组**由谁来做** —— 它是接管轴的开关。

| # | 控件必须回答的问题 | M1 谁做 | M2 谁做 | 怎么算做到了 |
|:--:|:---|:---|:---|:---|
| G1 | 我背后有没有一个真的原生窗口？ | 混合树（`NativeWidget` 有，自绘节点没有） | 全部没有 | 两种节点共存且行为一致 |

## 三、控件不负责什么（负面清单）

**这一节和上一节同样重要。** 正面清单说"要做什么"，负面清单挡住膨胀 —— 每条都写明不划清会怎样。

| 控件不负责 | 归谁 | 不划清会怎样 |
|:---|:---|:---|
| 事件路由（谁该收到、怎么冒泡） | `EventRouter` | 每个控件都长出一套自己的路由，行为不一致 |
| 裁剪（我画不到哪儿去） | `Window` + 平台 | 控件互相擦花 |
| DPI 换算 | `Window` | 每个控件都要知道屏幕缩放 |
| 决定自己的最终尺寸 | 布局 | 控件抢尺寸，父子打架 |
| 决定什么时候把像素刷到屏幕 | `Window` + `Renderer` | 控件各自刷屏，闪烁 |
| 平台消息与 `HWND` | `platform/` | **控件代码里出现 `#include <windows.h>`**（红线） |
| 无障碍暴露的实现（M1） | 系统（原生节点） | 自绘那天才发现要还债（M2 第 5 档） |

**一条红线**：`framework/` 和 `render/painter.h` 里**不出现 `#include <windows.h>`**。它一旦出现，就说明某一层职责漏了。

## 四、已拍板的归属决定

| # | 决定 | 落成什么 |
|:--:|:---|:---|
| 1 | **树统一路由**，事件由专门的组件处理；控件只表态"收不收"和"处理了没有" | `EventRouter` 组件 + `Widget::onEvent()` 返回值 |
| 2 | **`hitTest` 从 M1 就立接口** | `Widget::hitTest(Point)`；M1 混合实现（原生节点问系统，自绘节点框架算） |
| 3 | **基本布局从最开始就立好** | M1 就立 `Layout` 抽象，而不是先凑一个写死的排布 |
| 4 | **可见性两个开关分开**（像 CSS） | `visible`（画不画）与 `inLayout`（参不参与布局）正交 |
| 5 | **内边距 / 外边距按 CSS box model** | 属性属于控件，由布局读取消费 |

> 第 5 条是我按"像 CSS"推的，**没有单独确认过** —— 如果你要的是"padding 归布局"，说一声。

## 五、M1 的最小接口草案

清单落到接口上大概长这样（细节等名字定了再定）：

```cpp
// framework/widget.h
class Widget {
public:
    // A · 树
    Widget* parent() const;
    const std::vector<std::unique_ptr<Widget>>& children() const;
    Widget& addChild(std::unique_ptr<Widget> child);
    void removeChild(Widget& child);

    // B · 几何：固有尺寸自己答，最终矩形由布局强给
    virtual Size intrinsicSize(Size available) const = 0;
    void setBounds(const Rect& r);                 // 只有布局/父能调
    virtual bool hitTest(const Point& p) const;    // D1，M1 就立
    Thickness padding_;                            // B4

    // C · 绘制：只发指令
    virtual void onPaint(Painter& p, const Rect& damage) {}
    void invalidate(const Rect& r);
    void invalidateAll();

    // D · 事件：只表态，不路由
    virtual bool accepts(const Event& e) const;    // D2「我收不收」
    virtual bool onEvent(Event& e);                // D3「我处理了没有」

    // E · 状态
    Property<bool> visible_;                       // B6 画不画
    Property<bool> inLayout_;                      // B6 参不参与布局
};

// framework/event_router.h —— 专门的组件，控件不碰
class EventRouter {
public:
    bool dispatch(Widget& root, Event& e);         // 命中 → 捕获 → 目标 → 冒泡
};

// framework/layout.h —— M1 第一天就立
class Layout {
public:
    virtual Size measure(const Widget& container, Size available) = 0;
    virtual void arrange(Widget& container, const Rect& finalRect) = 0;
};
```

## 六、待拍板

1. **内边距归属** —— 我按 CSS 写的（控件属性、布局消费），确认一下
2. **命名** —— `visible` / `inLayout`、`EventRouter`、`intrinsicSize` 这些名字定不定
3. **M1 的事件类型集合** —— 建议只要五种：鼠标进出、按下、抬起、点击、文本变更 + 尺寸变更；其余留到 M2
4. **M1 立几个 `Layout` 实现** —— 建议两个：`StackLayout`（竖排，给自绘节点）+ `AbsoluteLayout`（固定矩形，给原生控件定位）

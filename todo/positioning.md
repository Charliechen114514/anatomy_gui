# 定位 · 器官主线与 Win32 遗产

> 本文是定位讨论的凝练。一条原则贯穿全文:**器官是身份,Win32 是遗产。**

## 一、结论

1. **器官当主线,Win32 降级为参考资料。** 导航第一层直接列 12 个器官;Win32 几十章原样保留,整体挪进"参考资料"类次级分区,不重写、不重组。
2. **顺序:先建器官页,再降级 Win32。** 器官页初期可以是"论点 + 指向 Win32 对应章节"的索引式短篇,先保证存在且可见。身份的转移是长出来的,不是砍出来的。
3. **微软侧标本只留 Win32 一个。** 现代部分补 COM 对象模型,不补 WinUI3 / WinForms / WPF。
4. **命名统一(待做)。** `hands_on_ur_own_gui` / MiniUI / "Anatomy GUI v2" / "自己动手写 GUI" 四名归一。

## 二、为什么

- **导航结构决定读者认知。** 导航是 Win32 打头,读者就以为是 Win32 教程;器官打头,读者才知道这是"讲 GUI 原理"的。
- **Win32 是地基。** WinUI3 / WinForms 底层仍是 HWND、消息循环、COM,只是盖了层壳把机制藏起来。Win32 老,是因为它离底层最近、藏不住——这正是教"看穿框架"时需要的。
- **"Win32 太老"是过滤器,不是缺点。** 嫌它老的人要的是快速出产品,正是反定位里"不服务"的那批人。
- **标本质量 > 数量。** 每加一个标本,前提都是亲手解剖过它;否则写出来就是 API 对比表,滑回手册。

## 三、器官清单(12 个,分层)

| 层 | 器官 |
|:---|:---|
| 底座(和 OS / 硬件打交道) | 窗口/表面、事件循环、输入、渲染、文本 |
| 中间(组织内容与逻辑) | 对象模型、控件树、布局、状态绑定 |
| 人因/现代(让真实用户用好) | 样式/主题、异步、可访问性 |

**完整性检验**:任一 GUI 框架的核心机制,必须能映射进上表;塞不进去就是漏了。
(例:Qt 信号槽 → 对象模型 + 状态绑定;React diff → 状态绑定;CSS → 样式。)

**可访问性是横切关注点**,不是单点器官:它要求每个控件额外暴露"名字/角色/值"给辅助技术,本质是对其他器官的一次二次描述。

**硬器官 vs 软器官**(决定 Act 4 的戏份):
- **硬器官**(不做就成不了框架):窗口、事件循环、输入、渲染、文本、控件树、布局、对象模型 —— Win32 全都有。
- **软器官**(老框架能糊弄、现代框架才做好):状态绑定、样式、异步、可访问性 —— Win32 原始或缺位。
- 比较解剖的"看穿"价值集中在**软器官**:那里 Win32 与 Qt / Web 反差最大;硬器官各家长得差不多,可比的少。

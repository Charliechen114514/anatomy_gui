## 三、第 1 步 · 具象：裸 Win32

**目标**：让读者看清 OS 的每一根线，**故意不做任何封装**。

**产出**：一个单文件 demo（约 250 行，不许有 `class`）+ 一篇讲述。

**规矩（这一段最关键）**：写完时，五条痛点必须还躺在代码里，不许顺手修掉。它们是第 2 步的全部原料。

| # | 痛点 |
|:--:|:---|
| 1 | 窗口对象无处安放（全局变量 / 把 `this` 硬塞进窗口用户数据） |
| 2 | 加一个控件要改三处 |
| 3 | 消息处理散在一个越来越长的分支里 |
| 4 | 缩放窗口后位置不会自己变，要手算 |
| 5 | 状态改了界面不动（忘了失效就花屏） |

**验收**（七条判据）：能点能输入 · 缩放重排不闪 · 中文正常 · 高 DPI 不糊 · 改状态界面更新 · 干净退出 · 一条命令构建。

**素材**：Win32 穿插清单 A–F 组，就地讲一两句，不展开成章节。

**内容产出**：一篇（或一组），主题就是"一个能跑的 Windows 程序，每一行都看得见"。

## 四、第 2 步 · 抽象：五个痛点，五层封装

**共性写法（五小步都用）**：前身 → 痛点 → 抽象 → 落回具象。**顺序不能换** —— 后一层都长在前一层上。

| 小步 | 前身是什么 | 抽象之后长什么样 | 素材先例 |
|:--:|:---|:---|:---|
| 2.1 窗口对象 | 全局变量 / 用户数据里塞指针 | 窗口句柄与对象一一对应，消息能找到自己的对象 | 老教程的"全局状态 → 实例数据 → OOP 包装"三步走的就是这条路 |
| 2.2 控件树 | 控件 ID 宏 + 创建调用 + 分支 | 父子成树，ID 自动分配，事件能找回对象 | 自己动手写 GUI 那条线的树思路 |
| 2.3 事件与事件路由 | 越来越长的消息分支 | 类型化事件 + 一个专门的路由组件；控件只表态"收不收""处理了没有" | — |
| 2.4 布局 | 手算坐标 | 布局抽象 + 两个最简实现（顺序排布 / 固定矩形） | — |
| 2.5 属性与重画 | 手写设置文本 + 手写失效 | 改属性 → 自动失效 → 自动重画 | — |

**验收（每小步）**：能指着第 1 步的代码说"它解决了这里"，并且第 1 步的那处别扭消失了。

**内容产出**：五篇，每篇一小步；四拍写法直接就是文章结构。

## 八、红线与卡点判据

**三条红线**：

1. `framework/` 与 `render/` 里**不出现 `#include <windows.h>`** —— 它一旦出现，说明某层职责漏了
2. **M1 代码总量 ≤ 1500 行** —— 超了说明这一步该拆
3. **每一步都要有肉眼可验证的验收** —— 写不出验收，就是这步定义得不对

**卡住时的判断**：

| 症状 | 说明什么 | 怎么办 |
|:---|:---|:---|
| 这层抽象写不出来 | 痛点不够疼 | 回第 1 步，把痛点做得更明显 |
| 这层抽象想不出用在哪 | 这一步不该做 | 删掉，别留着凑数 |
| 接口越写越多 | 边界没划 | 回控件行为清单的负面清单，把"不负责什么"补上 |
| 想在纸上把接口定死 | 该动手了 | 直接写代码，让代码定 |

**素材缺口（写到那一步之前必须先补）**：视觉样式绘制 · 重定向表面 · 系统的双缓冲 · 父子裁剪 · 无障碍暴露 —— 现有老教程里全是零处。

### 构建约定（已落地）

- **入口两条命令**：`cmake -G Ninja -B build -S .` + `cmake --build build -j`；**不用 CMakePresets**，也不需要开「开发者命令行」
- **工具链 clang-cl + Ninja**：clang-cl 自己定位 VS/SDK，所以**不需要 vcvars**；不产 `.sln` / `.vcxproj`；装它只要 `winget install LLVM.LLVM`
- **CMakeLists 会挡住非 clang-cl**：`COMPILER_ID=Clang` 且 `SIMULATE_ID=MSVC` 才放行；找不到 clang-cl 时当场给出安装命令
- **单配置，默认 Debug**；**静态 CRT（/MT）** —— 产物双击就跑，只依赖 USER32/KERNEL32
- **顶层选项**：`/utf-8 /std:c++20 -Wall -Wextra`，另关掉 `-Wno-c++98-compat` 与 `-Wno-nonportable-system-include-path`（理由写在 CMakeLists 注释里）；产物统一落 `build/bin/`
- **IDE**：`.vscode/settings.json` —— CMake Tools 驱动 configure/build（`cmake.generator: Ninja`），补全交给 clangd 读 `build/compile_commands.json`
- ⚠ **PowerShell 坑**：`cmake -DXXX=$Var` 这种裸参数里，`=` 后面的变量**不会展开**（传进去是字面量 `$Var`）；必须写成 `"-DXXX=$Var"` 或数组展开
- ⚠ **生成器没法在 CMakeLists 里定**：想「不加 `-G` 也是 Ninja」，设一次 `CMAKE_GENERATOR=Ninja`；不设则装了 VS 的机器会选 VS 生成器并产出 `.sln`

### 已解决的坑（留着当教材）

| 坑 | 现象 | 结论 |
|:---|:---|:---|
| 中文版 cl 的 `/showIncludes` 前缀被本地化 | 刷 231 行「注意: 包含文件:」，`build/.ninja_deps` 只有 88 字节（空）→ **改 `.h` 不重编** | 换 clang-cl 后彻底消失：clang-cl 走 GCC 风格的 `-MD/-MT/-MF` depfile，与 `msvc_deps_prefix` 无关。`VSLANG=1033` 对 cl **实测无效** |
| MSVC 配 Ninja 必须先进 vcvars 环境 | 裸跑 `cmake -G Ninja` 报找不到编译器，于是要写一个补 vcvars 的脚本 | clang-cl 自己定位 VS/SDK，这一笔税不用交 —— 那个 `scripts/build.ps1` 因此删掉了 |
